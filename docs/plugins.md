# Serpantinum plugin system (experimental)

Serpantinum can discover external plugins, load their main QML entry point, expose them in Settings and integrate optional plugin surfaces into the shell.

## Plugin locations

Plugins are discovered from two roots:

1. Built-in plugins: `$QS_DIR/plugins/builtin/<plugin-id>/plugin.json`
2. User plugins: `${XDG_CONFIG_HOME:-~/.config}/serpantinum/plugins/<plugin-id>/plugin.json`

If the same `id` exists in both roots, the user plugin wins. This makes local development and overriding built-ins possible without modifying the built-in copy.

## Manifest

Minimal `plugin.json`:

```json
{
  "id": "author/example",
  "name": "Example",
  "version": "0.1.0",
  "apiVersion": 1,
  "entry": "Plugin.qml",
  "enabledByDefault": true
}
```

`apiVersion` must not be newer than `PluginManager.apiVersion`. The loader verifies declared entry files before exposing the plugin.

Useful optional metadata:

```json
{
  "barEntry": "Bar.qml",
  "barLabel": "Example",
  "barIcon": "󰏗",
  "barColor": "mauve",
  "capabilities": ["panel", "bar"]
}
```

When `barEntry` is present, the plugin becomes a first-class Serpantinum bar module.

## Main entry contract

The main QML entry root must expose:

```qml
property var pluginMetadata: ({})
property string pluginDirectory: ""
```

`PluginHost` fills those properties and registers the live plugin instance with `PluginManager`. A main entry can own shared state, timers, IPC handlers, background services and independent Wayland surfaces.

## Bar entry contract

A plugin that declares `barEntry` appears in **Settings → Bar → Bar configuration** alongside native modules. It can be dragged between left/center/right, reordered and grouped with native modules. The same layout is mapped to top/center/bottom when the bar is vertical.

The bar entry root exposes a `host` property:

```qml
import QtQuick

Item {
    property var host

    implicitWidth: label.implicitWidth
    implicitHeight: label.implicitHeight

    Text {
        id: label
        text: host && host.pluginInstance ? host.pluginInstance.someText : "Plugin"
        color: host ? host.theme.text : "white"
    }
}
```

`PluginBarModule` owns the Serpantinum chrome: background, rounded corners, hover state, padding, opacity, grouping and layout animations. Plugin bar entries should normally render content only.

The host currently exposes:

- `host.pluginData` — manifest data.
- `host.pluginInstance` — live main-entry instance.
- `host.theme` — `ThemeBackend`.
- `host.vertical` — `true` on left/right bars.
- `host.compact` — compact/grouped presentation hint.
- `host.hovered` — shell hover state.
- `host.s(value)` — Serpantinum scaling helper.
- `host.activate()` — default activation; calls `activateBar()` or `togglePanel()` on the plugin instance.
- `host.pluginSetting(key, fallback)` / `host.setPluginSetting(key, value)` — per-plugin settings.

A plugin can implement `activateBar()` on its main entry to override the default click action. If absent, `togglePanel()` is used when available.

Bar module IDs are generated by the host as `plugin:<plugin-id>` and saved directly in the normal `bar.modules` layout. Plugins therefore use the same persistence and grouping model as native Serpantinum bar modules.

## Enable / disable

Plugins default to `enabledByDefault`. Per-plugin state is stored in normal Serpantinum settings:

```json
{
  "plugins": {
    "serpantinum.timer": {
      "enabled": false
    }
  }
}
```

Disabling a plugin keeps its bar placement in the configuration but collapses the module to zero size. Re-enabling it restores the same position.

The Plugins settings page can also add/remove a plugin from the bar. New modules are inserted in the center by default; the exact position is then managed from **Settings → Bar**.

## Installing plugins

Settings → Plugins accepts a Git repository URL. The installer clones it into the user plugin directory, validates `plugin.json`, checks API compatibility and validates both `entry` and `barEntry` when present.

The repository currently needs `plugin.json` at its root.

## Built-in Timer reference plugin

The Timer is the reference implementation for the current API. It contains:

- `Plugin.qml`: countdown state, panel and IPC API.
- `Bar.qml`: lightweight bar content.
- `plugin.json`: manifest with `barEntry`.

IPC smoke test:

```bash
qs ipc call plugin-timer toggle
qs ipc call plugin-timer start 300
qs ipc call plugin-timer pause
qs ipc call plugin-timer reset
```

## Security

Plugins are trusted QML code and are **not sandboxed**. A plugin loaded by Serpantinum runs with the same user privileges as the shell and can use Quickshell APIs or spawn processes. Only install plugins whose source you trust.

## Current limitations

- No plugin store or updater.
- No dependency resolution.
- No permission model or sandbox.
- No automatic hot reload of arbitrary plugin source changes.
- No stable launcher-provider API yet.
- No first-class desktop-widget plugin API yet.

The bar API is intentionally host-driven so future plugins inherit Serpantinum behavior without duplicating shell styling or layout logic.
